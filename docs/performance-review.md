# 手机性能检查

检查日期：2026-09-06。对象为实验分支的本地正式构建，未部署。页面覆盖首页、Rumata 案例与 31 个 Agent 长文，分别代表 3D 场景、案例档案和长篇阅读。

## 测试条件

- Lighthouse 13.4.1、Chrome 152.0.7977.76，独立浏览器配置，每页串行测量两次，保留两次结果。
- 手机视口 390 × 844、DPR 1、Android 用户代理；CPU 降速 4 倍，网络模拟为 150 ms RTT / 1,638.4 Kbps。Lighthouse 使用 `simulate` 方法。
- 浏览器冷缓存，服务端缓存并非冷缓存。服务位于 localhost，结果不包含生产 CDN、跨地域网络或服务器冷启动。
- 实际硬件是 macOS / Apple M4，GPU 为 ANGLE Metal Apple M4。手机尺寸和 CPU 降速不能等同于真实安卓或 iPhone 的 GPU、温度与耗电表现。
- 独立浏览器截图与页面状态确认了首页 3D 实际加载、正文可读，未出现此前的 headless 动画冻结。

LCP 表示主要内容显示时间，CLS 表示布局跳动，TBT 表示加载期间主线程阻塞。以下为实验室数据，不能代替真实用户的 Core Web Vitals，尤其不能用 TBT 代替实际 INP。[Web Vitals 官方说明](https://web.dev/articles/vitals)

## 已定位的问题与修复

1. 房间内四份小图原先下载原图，再在浏览器缩小。浏览器网络记录确认下载了 2,319,305 字节。现在使用既有图片优化服务生成适合纹理的版本，四份 WebP 响应共 361,818 字节，减少约 84.4%；原始图片、场景构图和纹理内存上限保留。
2. 中文字体在首页、案例、长文分别产生约 439 KB、556 KB、1.35 MB 下载；原字体 CSS 还为同一组分片重复声明三个字重，压缩后约 102 KB。使用相同字体的本地字形子集，保留现有字重和中英文排版，具体来源与维护方法见 [字体维护说明](site-fonts.md)。
3. 文章正文图片原先直接下载原图。网页现根据阅读栏和屏幕选择适合的尺寸，保留原始比例、占位尺寸、替代文字和延迟加载；RSS 与 Markdown 继续使用可独立读取的原始图片地址。
4. 案例首屏封面明确使用高加载优先级。首页日光与暮色的两份预览合计约 26 KB，本轮未为这项较小开销改动静态 HTML 与用户光线偏好的恢复方式。

## 最终复测

与修复前采用相同条件，每页两次；传输量为两次平均值，MB 使用十进制。可核对的逐次指标保存在 [测量数据](performance-results.json)。

| 页面 | FCP（秒，两次） | LCP（秒，两次） | TBT（毫秒，两次） | CLS | 总传输量 | 传输减少 |
| --- | --- | --- | --- | --- | --- | --- |
| 首页 | 3.312 / 3.314 | 5.262 / 4.964 | 69 / 98 | 0.0202 | 1.419 MB | 59.4% |
| 案例 | 3.310 / 3.308 | 4.810 / 4.808 | 8 / 10 | 0 | 0.743 MB | 23.8% |
| 长文 | 3.610 / 3.607 | 5.035 / 4.957 | 18 / 11 | 0 | 0.773 MB | 68.0% |

长文 LCP 均值从约 12.24 秒降到 5.00 秒，案例从 6.46 秒降到 4.81 秒，首页从 6.94 秒降到 5.11 秒。最终六次 Lighthouse 均无运行警告，但模拟 LCP 仍然偏慢，不能据此声称手机性能已经最优。

另外通过 Chrome CDP 实际限制网络和 CPU，每页观察一轮，条件为下载 1,638.4 Kbps、上传 675 Kbps、延迟 150 ms、CPU 降速 4 倍。该组没有改动前基线，不能与上方 Lighthouse 模拟结果相减。

| 长文 | 1.128 秒 | 1.128 秒 | 0 | 不自动加载 3D |

首页先展示内容和房间预览，再加载完整场景，LCP 不代表 3D 就绪。两类测试采用不同模型和取样方式，需分别解读。

浏览器实际网络记录确认，长文首图在手机选择了 384 像素宽版本，传输 12,108 字节，原图约 630 KB。三页字体传输均约 423 KB，英文首页只加载 Geist 与 Noto Latin，未下载 CJK。平台字体检查确认三页标题与文章小标题实际使用自定义 Noto Serif SC；没有通过字体回退获得更快的结果。样式表传输从约 153 KB 降到约 54 KB。

五次最终交互样本分别为：打开菜单 64 ms、关闭菜单 32 ms、切换光线 48 ms、选择工作区 72 ms、关闭工作区 48 ms。状态变化均成功，场景保持就绪。这些单次样本不能用来判断线上 INP 或每项交互的实际改善幅度。

## 功能与抓取验证

57 项测试通过，包含全部 6 篇文章的图片尺寸、替代文字、正文与链接不变，以及 RSS 保留原图地址的检查。代码检查、类型检查和正式构建通过；抓取审计覆盖 34 个页面、11 张分享图片与 22 份机器可读信息源，无失败。手机浏览器检查覆盖首页、案例、文章及英文首页，未见页面错误和横向溢出。

原始 Lighthouse 报告、截图和交互记录留在本机 `/tmp/darren-perf-baseline/` 与 `/tmp/darren-perf-after-final/`，这些临时文件不保证长期保留。仓库中的测量数据保存了最终与基线指标及测量条件。字体别名继承问题导致的中间构建已排除，未计入成果。

## 验证边界

发布后仍需结合真实用户数据确认加载、交互与布局稳定性。真实 iOS / Android、Safari、低端设备的持续 3D 表现、温度和耗电本次未测。搜索收录、AI 引用与合作咨询的变化也不属于本地性能测试能够证明的结果。
