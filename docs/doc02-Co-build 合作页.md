## 3）How we co-build（我们怎么一起做）

### 标题

**协作方式**


#### 模式 A：共创冲刺

**适合：**你已经有 idea / 半成品 / repo
**目标：**ship 一个可展示、可讲清楚、可传播的版本
**产出：**

* 可上线交互的 MVP 产品
* storytelling

---

#### 模式 B：From demo → product（产品化）

**适合：**你已经有 demo，但想把它变成更像产品
**目标：**从“能跑”到“有人愿意用”
**产出：**

* 核心 user journey
* 功能优先级 / 迭代节奏
* 最小增长动作（比如通过活动/社群拿反馈）

---

#### 模式 C：Co-host event（共办活动）

**适合：**你有场地/资源/社区，想做 workshop / buildathon
**目标：**把活动变成持续聚人的方向
**产出：**

* 活动机制设计（题目、流程、评审、物料）
* 导师/伙伴协作
* 传播与增长

---

## 6）协作原则

### 标题

**Principles / 协作原则**

* 直接、清晰、少内耗
* 偏好 async（文字/文档），必要时再开会
* 任何合作都以“交付”为核心
* 不做长期务虚讨论（除非明确是探索）

---

## 7）不适合的情况


### 标题

**可能不适合**

* 只想聊概念，不想做东西
* 希望我“代做/外包/咨询交付”，但自己不参与
* 只要资源与曝光，不愿意长期共创
* 把合作当成甲乙方，而不是共同交付
